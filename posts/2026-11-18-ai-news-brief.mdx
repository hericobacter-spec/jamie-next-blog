# 최신 AI 연구 동향 (2026년 11월 18일)

> **기준 시각:** 2026년 11월 18일 오전 9시(KST). 11월 15~18일 공개된 공식 발표와 ArXiv 메타데이터를 우선 확인했습니다. 기업이 공개한 성능 수치는 독립 재현 전까지 발표사 기준의 결과로 읽어야 합니다.

## 오늘의 핵심

- OpenAI가 **GPT-6.2 Astra**와 **GPT-6.2 Sol**을 공개하며 전문 업무, 코딩, 컴퓨터 사용, 비용 효율을 동시에 겨냥했습니다.
- AI 제품의 경쟁 지점이 대화형 답변에서 **영업·법률·연구·의료 업무를 끝까지 처리하는 에이전트**로 이동하고 있습니다.
- 최신 연구는 모델 크기 자체보다 요구사항 추적, 실행 검증, 메모리 비용, 실제 로봇 제어와 같은 **완주 품질**을 집중적으로 측정합니다.

## 1. GPT-6.2 Astra와 Sol: 성능뿐 아니라 업무 단가를 겨냥한 세대교체

OpenAI는 11월 17일 GPT-6.2 Astra와 GPT-6.2 Sol을 발표했습니다. Astra는 복잡한 프로젝트와 전문 작업을 위한 프런티어 모델, Sol은 일상적인 작업을 빠르고 효율적으로 처리하는 모델로 포지셔닝됐습니다. 공식 설명에 따르면 두 모델은 ChatGPT Work, Codex, API에서 전문적인 결과물, 코딩, 컴퓨터 사용 능력을 개선하면서 더 적은 출력 토큰과 낮은 비용을 목표로 합니다.

이번 발표에서 중요한 점은 단순한 벤치마크 점수 경쟁보다 **에이전트의 작업 단위 경제성**을 전면에 내세웠다는 것입니다. 코딩 에이전트가 긴 계획을 세우고 브라우저나 터미널을 조작할수록 추론 토큰·도구 호출·실패 재시도 비용이 커집니다. 따라서 같은 품질을 더 짧은 출력과 적은 재시도로 달성한다면 실제 업무 자동화의 총비용이 낮아질 수 있습니다. 다만 제품별 가격, 사용량 제한, 장기 작업의 실패율은 별도로 확인해야 합니다.

## 2. 영업·법률 에이전트: 범용 모델이 조직의 업무 표면으로 들어가다

OpenAI는 같은 날 **ChatGPT for Sales**도 공개했습니다. 새 Sales 플러그인과 30개 이상의 신규·확장 파트너 플러그인을 통해 잠재 고객 조사, 제안서 준비, CRM 업데이트, 영업 기회 후속 조치를 지원하는 흐름입니다. 핵심은 영업 담당자가 질문에 답을 얻는 데서 끝나는 것이 아니라, 조사 결과를 조직 시스템에 반영하고 다음 행동으로 이어지게 하는 것입니다.

법률 분야에서는 **Astra for Law**가 출시 평가의 24개 법률 영역에서 1위를 기록했다는 발표가 나왔고, ChatGPT Enterprise 고객은 접근을 요청할 수 있게 됐습니다. 법률 업무는 그럴듯한 문장보다 인용 근거, 관할권, 최신성, 누락된 쟁점의 통제가 중요합니다. 따라서 이 제품군의 실사용 가치는 모델의 일반 지능보다 문서 출처 연결, 검토자 승인, 변경 이력과 같은 워크플로 설계에서 갈릴 가능성이 큽니다.

## 3. 연구·안전 인프라 확장: 접근성 확대와 독립 평가를 동시에

OpenAI는 11월 16일 ChatGPT for Academic Researchers 프로그램을 확대해 전 세계 연구자 20만 명에게 프런티어 모델 무료 접근을 제공한다고 밝혔습니다. 또 1,800명 이상의 과학자가 ChatGPT를 연구에 활용하는 방식과 생산성 변화를 정리한 자료를 공개했습니다. 연구자가 모델을 실제 분석·문헌·코딩 작업에 쓰는 사례가 늘수록, 앞으로는 모델의 평균 답변 품질뿐 아니라 재현 가능한 실험 기록과 데이터 출처가 중요해집니다.

같은 날 Apollo Research, METR, Transluce, Goodfire와 함께 모델 정렬, 안전장치, 모니터링 체계를 독립적으로 평가하는 **embedded assessments**의 첫 단계를 시작한다고 발표했습니다. 고성능 모델을 배포하는 속도만큼, 모델이 어떤 조건에서 안전장치를 우회하거나 장기 목표를 잘못 추적하는지 외부 평가로 확인하려는 흐름입니다. 아동 안전 영역에서는 AI 생성 자료를 포함한 잠재적 아동 성착취물을 식별하는 분류기와 대응 도구도 공개했습니다. 안전 기능은 모델 카드의 선언보다 실제 운영 환경의 오탐·누락·검토 비용으로 평가해야 합니다.

## 4. K2-Horizon: 완전 공개를 내세운 오픈 모델 제품군

ArXiv에 공개된 **K2-Horizon**은 0.9B급 밀집 모델부터 375B-A23B MoE까지 여섯 개 모델로 구성된 오픈 언어 모델 제품군입니다. 수학·과학, 소프트웨어 엔지니어링, 딥 리서치, 오피스 자동화 등 에이전트형 작업을 겨냥하고, Mixture-of-Value Attention과 softplus attention gating을 제안합니다. 36B-A4B 모델은 활성 파라미터를 줄이면서 같은 데이터로 학습한 32B 밀집 모델에 근접한다고 보고했습니다.

특히 모델 가중치만 공개하는 수준을 넘어 중간 체크포인트, 사전학습 데이터, 학습 로그, 평가·인프라 코드와 약 10T개의 합성 사전학습 토큰을 만든 파이프라인까지 공개하겠다고 한 점이 눈에 띕니다. 오픈 모델의 경쟁력이 다운로드 가능 여부에서 **재현성과 개발 과정의 투명성**으로 이동하고 있다는 신호입니다.

## 5. SWE-CoWork: 코딩 에이전트는 구현보다 조직 업무 완주가 어렵다

**SWE-CoWork**는 실제 저장소 101개, 11개 프로그래밍 언어, 12개 도메인의 개발 과제 101개를 이용해 코딩 에이전트를 ‘조직의 디지털 직원’처럼 평가합니다. 에이전트는 26명의 가상 동료에게 질문하고, 흩어진 업무 기록에서 요구사항을 복원하며, 충돌하는 정보를 조정한 뒤 비공개 실행 테스트를 통과해야 합니다.

11개 모델 평가에서 상위 모델은 fail-to-pass 테스트의 약 63%를 만족했지만, 과제 전체를 완주한 비율은 8% 미만이었습니다. 요구사항을 처음부터 모두 제공하면 일부 모델의 테스트 성능은 약 16%포인트 개선됐지만, 완전한 과제 성공률은 바뀌지 않았습니다. 이는 현재 코딩 에이전트의 병목이 코드 생성만이 아니라 **질문한 요구사항을 끝까지 추적하고, 구현 후 검증하고, 누락된 일을 다시 회수하는 운영 루프**에 있음을 보여줍니다.

## 6. ScaleVLA: 프런티어 VLM을 로봇의 행동 표현으로 연결

**ScaleVLA**는 552B 파라미터 DeepSeek-V4.1-Flash 백본과 행동 DiT를 연결해 비전-언어-행동 모델의 규모 효과를 비교했습니다. 논문 보고에 따르면 10개의 시연만 사용해도 50개 시연으로 학습한 2B 백본을 넘는 결과를 보였고, LIBERO-PRO 일반화 성공률은 45.1%로 더 작은 백본의 최대 31.3%보다 높았습니다. 실제 충전기 삽입 작업도 10회 중 9회 성공해 작은 백본의 4회보다 개선됐으며, 행동 청크 기준 중앙 지연은 216ms로 보고됐습니다.

이 결과는 큰 언어 모델이 텍스트 추론에만 쓰이는 것이 아니라 물리적 행동에 필요한 시각적 표현의 기반이 될 수 있음을 시사합니다. 그러나 시뮬레이션과 제한된 하드웨어 과제의 성능이 곧바로 일반 가정·공장 환경의 안전한 조작을 의미하지는 않습니다. 접촉 실패, 가림, 물체 편차, 비상 정지 같은 분포 밖 조건의 검증이 다음 단계입니다.

## 7. Accelerate Bench와 PaperCritic: ‘맞는 답’보다 실행 가능한 검증을 측정

**Accelerate Bench**는 과학·슈퍼컴퓨팅 프로그램에서 가져온 32개 CPU 최적화 과제로 코딩 에이전트를 평가합니다. 실행 가능한 프로그램의 정확성을 유지하면서 실제 속도 향상을 만들어야 하며, 16개 에이전트의 Score@1은 25.5~67.4% 범위였습니다. 두 상위 에이전트는 32개 중 22개 이상에서 최소 2배 속도 향상을 달성했지만, 동일한 코드도 빌드·런타임 설정에 따라 0.29~2.12배로 달라질 수 있었습니다. 코드 변경 자체만큼 측정 환경과 재현 조건이 중요하다는 뜻입니다.

**PaperCritic**은 1,000개 ICLR 제출물에서 만든 2.3만 개 검토 포인트로 논문의 건전성만 평가하는 AI 리뷰어를 학습했습니다. 정밀도와 재현율의 F1을 보상으로 강화학습하고, 인용은 원문 검색, 수학은 컴퓨터 대수, 수치는 실행 코드로 확인하는 도구 기반 검토를 결합했습니다. AI가 생성한 결과를 다시 AI가 판단하는 시대에는 ‘설득력 있는 설명’보다 **인용·수식·실행 결과를 연결한 검증 흔적**이 더 중요한 품질 신호가 됩니다.

## 오늘의 시사점

1. **모델 출시의 기준이 업무 완주로 이동했습니다.** Astra·Sol 같은 프런티어 모델은 답변 품질뿐 아니라 토큰·도구 호출·재시도 비용까지 경쟁합니다.
2. **에이전트 평가는 요구사항과 상태를 추적해야 합니다.** SWE-CoWork처럼 부분 테스트 통과와 최종 과제 완주를 분리하면 현재 시스템의 실제 병목이 드러납니다.
3. **물리·과학 영역에서는 근거와 안전이 제품 기능입니다.** 로봇 행동의 접촉 검증, 연구 결과의 재현성, 안전장치의 독립 평가가 모델 성능만큼 중요합니다.
4. **오픈 모델의 차별화는 투명한 개발 과정으로 넓어지고 있습니다.** K2-Horizon처럼 데이터·로그·코드를 함께 공개하면 성능 비교를 넘어 재현 가능성과 감사 가능성을 경쟁할 수 있습니다.
