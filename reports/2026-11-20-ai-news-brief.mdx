# [NEWS] 2026-11-20 AI 뉴스 브리프: 에이전트의 행동이 제품이 된 날

## 한줄 요약

오늘 공개된 AI 제품의 공통점은 모델이 대화창 안에서 답을 생성하는 데 머물지 않고 **화면을 조작하고, 고객 사건을 처리하고, 성능 회귀를 고치고, 가상 세계를 만들고, 브라우저 안에서 추론하는 것**입니다. Google은 Gemini 앱에서 Mac의 로컬 앱·파일·웹을 다루는 컴퓨터 사용 기능을 공개했고, AWS는 SOP를 업무 계획으로 바꿔 환불·분쟁·사기 조사·보험 청구를 처리하는 Resolutions를 일반 공개했습니다. OpenAI는 Codex 에이전트로 성능 문제를 탐지하고 수정·배포 후 검증하는 Performance Factory를 소개했습니다.

이 흐름은 에이전트의 경쟁 기준을 바꿉니다. 이제 질문은 “모델이 얼마나 똑똑한가”만이 아니라 “어떤 화면과 권한을 봤는가, 어떤 정책을 적용했는가, 어떤 변경을 남겼는가, 결과가 틀렸을 때 누가 중단하고 되돌리는가”가 됩니다. 최신 연구도 같은 결론을 보강합니다. 사람과 에이전트의 기억을 맞추는 방법, 사용자 시뮬레이터의 허점을 찾는 방법, AI 공급망의 집중 위험을 지도화하는 방법, 모델의 자기 확신과 실제 정확도를 구분하는 방법이 모두 운영 신뢰성의 문제로 수렴합니다.

## 오늘의 핵심 포인트

- **컴퓨터 사용은 별도 창·앱별 권한·실시간 미리보기·핵심 행동 승인과 함께 제품화됐습니다.** 자율성보다 관찰 가능성과 중단 가능성이 먼저 배치됐습니다.
- **기업 업무 에이전트는 SOP를 실행 계획으로 바꾸고, 예외만 사람에게 올리는 방향으로 이동합니다.** 계획·정책·승인·감사 기록이 한 작업 단위가 됩니다.
- **코드 에이전트의 가치는 생성된 패치보다 회귀를 발견하고 복구했는지로 측정됩니다.** 조사·수정·배포·사후 확인이 하나의 폐쇄 루프가 됩니다.
- **생성형 월드 모델과 온디바이스 모델은 에이전트의 실행 공간을 넓힙니다.** 시뮬레이션과 브라우저 내 추론이 실제 행동 전의 시험장과 로컬 처리 계층이 됩니다.
- **평가의 평가가 중요해졌습니다.** 사용자 시뮬레이터가 잘못된 목표·누락된 제약·고장난 결과를 받아들이면 에이전트 벤치마크 점수도 믿을 수 없습니다.
- **기억·공급망·인간 검토자의 품질도 측정 대상입니다.** 자동화의 성공은 모델 점수 하나가 아니라 시스템 전체의 정렬과 감사 가능성으로 판단해야 합니다.

## 산업 뉴스와 제품 흐름

### 1. Gemini가 Mac의 화면을 뒤에서 조작한다

Google은 11월 19일 Gemini 앱 for Mac의 컴퓨터 사용 기능을 공개했습니다. 사용자가 자연어로 작업을 설명하면 Gemini가 로컬 파일, 데스크톱 앱, 웹사이트를 오가며 메뉴를 열고, 정보를 입력하고, 버튼을 클릭하는 다단계 작업을 수행합니다. 기능은 영어·미국에서 먼저 출시되며, Apple Silicon Mac과 macOS Sequoia 15.0 이상이 필요합니다.

안전 설계의 핵심은 Gemini가 사용자의 현재 화면과 커서를 가로채지 않는 별도 격리 창에서 실행된다는 점입니다. 사용자는 어떤 앱에 접근할지 정하고, 실시간 미리보기를 보고, 언제든 일시정지하며, 핵심 행동이 발생하기 전에 승인할 수 있습니다. Google이 제시한 예시에는 로컬 PDF에서 무게·치수·주소를 추출해 배송 견적 양식에 입력하거나, 대시보드의 지표와 스크린샷을 모아 프레젠테이션을 만드는 작업이 포함됩니다.

이 기능이 중요한 이유는 브라우저 에이전트가 웹페이지 안에서만 작동하는 도구가 아니라 운영체제와 애플리케이션의 경계를 넘는 실행 계층이 되었기 때문입니다. 화면을 읽는 것 자체보다 위험한 것은 읽은 정보를 어느 앱에 입력하고 어떤 외부 변경을 일으키는가입니다. 따라서 실제 도입 시에는 앱별 권한 외에도 다음을 기록해야 합니다.

- 에이전트가 읽은 파일과 화면의 목록
- 웹페이지와 로컬 앱에서 가져온 지시의 출처
- 입력·클릭·파일 변경 전후의 상태
- 승인된 행동과 자동으로 실행된 행동의 구분
- 중단 시점에 남은 임시 파일·양식·외부 상태

컴퓨터 사용 에이전트에서 “사용자가 볼 수 있었다”는 것과 “사용자가 실제로 이해하고 승인했다”는 것은 다릅니다. 미리보기는 증거의 시작일 뿐이며, 승인 화면에는 변경 대상·영향 범위·되돌리기 방법이 함께 보여야 합니다.

### 2. AWS Resolutions: 고객 사건을 Work plan으로 바꾸다

AWS는 Amazon Connect Resolutions를 11월 19일 일반 공개했습니다. 이 서비스는 환불 요청, 거래 분쟁, 사기 조사, 보험 청구처럼 대량으로 발생하는 운영 업무를 AI 에이전트와 결정론적 워크플로의 조합으로 처리합니다. 관리자는 자연어로 프로세스를 설명하거나 표준 운영 절차(SOP)를 업로드하고, Resolutions는 예외 조건·판단 규칙·승인 임계값을 확인하는 질문을 거쳐 Work plan을 생성합니다.

각 요청은 Resolutions Case가 되고, 에이전트는 내부 애플리케이션에서 정보를 모으고 정책을 적용하며 고객에게 누락된 정보를 요청합니다. 사전에 정의된 업무 단계는 기본 에이전트, 조직이 구성한 에이전트, 자체 에이전트가 수행할 수 있고, 사람은 승인과 예외 처리에 집중합니다. AWS는 거래 분쟁 사례로 거래 이력과 차지백 규칙을 확인하고, 영수증을 요청하고, 임시 환급을 발행한 뒤 판단이 필요한 사건만 전문가에게 올리는 흐름을 제시합니다. 모든 행동과 결정은 기록되어 실시간 진행률·업무량·서비스 수준 위험을 감사할 수 있게 합니다.

여기서 중요한 것은 LLM이 SOP를 읽는다는 사실이 아니라, 모호한 SOP를 실행 전에 명시적인 규칙과 승인 경계로 바꾼다는 점입니다. 실제 기업 프로세스에는 “특정 금액 이상이면 관리자 승인”, “신원 확인이 끝나지 않으면 환불 금지”, “고객 기록이 서로 다르면 보류” 같은 암묵적 조건이 있습니다. 에이전트가 이런 조건을 추정해 실행하는 대신, Work plan 생성 단계에서 질문으로 드러내면 운영·법무·감사팀이 검토할 수 있습니다.

기업은 Resolutions 같은 시스템을 도입할 때 처리율만 보지 말아야 합니다. 예외가 누락되지 않았는지, 정책 변경이 기존 사건에 어떻게 적용되는지, 자동 처리와 사람 승인 사이의 경계가 일관적인지, 결과가 고객에게 어떤 근거로 설명되는지를 함께 측정해야 합니다.

### 3. OpenAI Performance Factory: 코딩 에이전트가 회귀를 닫힌 루프로 처리한다

OpenAI는 Codex 기반의 Performance Factory를 소개했습니다. 이 시스템은 성능 경고가 발생하면 에이전트가 문제를 조사하고, 원인을 작업에 기록하고, 수정안을 제안하며, 엔지니어 검토와 배포가 끝난 뒤 성능이 기준선으로 돌아왔는지 다시 확인하는 흐름을 자동화합니다.

OpenAI의 설명에 따르면 첫 번째 Regression Workflow는 3개월 조금 넘는 기간에 1,700건 이상의 조사를 추적했고, 600건 이상의 사례에서 근본 원인을 찾았습니다. 이 공장은 설정 가능한 작업 추적기, 준비된 일을 에이전트에 배정하는 디스패치 루프, 클라우드에서 Codex를 실행하는 API, GitHub 리뷰 댓글이나 배포 완료 같은 사건이 발생했을 때 에이전트를 깨우는 구독 구조로 구성됩니다.

이 사례가 시사하는 것은 코드 에이전트의 성능을 “한 번에 좋은 코드를 작성했는가”로 평가하기 어렵다는 점입니다. 프로덕션 시스템에서는 성능 회귀의 원인이 코드, 데이터, 인프라 설정, 트래픽 변화, 배포 순서 중 어디에 있는지 구분해야 합니다. 수정안이 효과가 있었는지 확인하려면 배포 전후 같은 지표와 기준선이 필요합니다. 따라서 에이전트는 생성기라기보다 사건 처리 시스템의 한 구성요소가 됩니다.

실무 체크포인트는 세 가지입니다. 첫째, 에이전트가 원인 분석과 가설을 기록하되 로그를 사실로 위장하지 않게 해야 합니다. 둘째, 변경 승인과 배포 권한을 분리해야 합니다. 셋째, 사후 검증이 실패했을 때 자동으로 원복하거나 사람에게 재할당할 수 있어야 합니다. 조사·수정·검증이 서로 다른 도구에 흩어지면 “고쳤다고 보고했지만 실제로는 기준선으로 돌아오지 않은” 상태를 놓칠 수 있습니다.

### 4. Genie 4 API: 생성형 월드가 에이전트의 시험장이 된다

Google은 Genie 4를 Gemini API와 Google AI Studio에서 사용할 수 있게 했습니다. 텍스트 프롬프트, 참조 이미지 또는 두 가지를 함께 입력해 720p·초당 24프레임의 연속적인 가상 세계를 생성하고, 주변음·효과음·캐릭터 대화가 동기화된 결과를 만들 수 있습니다. 실시간 키보드 입력과 텍스트 프롬프트로 날씨·조명·객체·사건을 바꿀 수 있으며, Google은 Gemini의 추론이 세계 상태의 일관성을 유지한다고 설명합니다. 출력에는 보이지 않는 SynthID 워터마크가 포함됩니다.

Genie 4는 게임이나 시각 디자인만을 위한 도구가 아닙니다. Google은 인터랙티브 경험, 공간 개념 시각화, 로보틱스와 AI 에이전트 훈련을 사용 사례로 제시합니다. 에이전트가 실제 환경에서 행동하기 전에 다양한 조건을 저렴하게 생성해 볼 수 있다는 점에서 월드 모델은 시뮬레이션 계층의 역할을 할 수 있습니다.

다만 생성된 세계가 실제 세계를 정확히 반영한다는 뜻은 아닙니다. 물리 법칙, 센서 노이즈, 사람의 예측 불가능성, 장비 고장은 시뮬레이션에 충분히 표현되지 않을 수 있습니다. 월드 모델을 학습·평가에 사용할 때는 생성 환경에서의 성공률을 현장 안전성으로 번역하지 말고, 실제 데이터와 하드웨어에서 독립적으로 검증해야 합니다. 또한 생성된 장면·음성·사건의 출처와 워터마크를 보존해 훈련 데이터와 평가 데이터가 섞이지 않게 해야 합니다.

### 5. Edge의 Aion Instruct: 웹에서 클라우드와 온디바이스가 함께 추론한다

Microsoft는 Edge에 내장되는 23억 파라미터 규모의 오픈 웨이트 모델 Aion Instruct를 일반 공개하고, 웹사이트에서 Prompt API를 사용할 수 있는 오리진 트라이얼을 시작했습니다. Aion은 기존 Phi-4-mini를 대체하며 텍스트 생성·요약·지시 따르기·구조화 출력 같은 웹 작업을 로컬에서 수행하도록 설계됐습니다. Prompt API는 기기에서 모델을 실행할 수 있을 때 사용하고, 더 강한 추론이나 기기 호환성이 필요할 때 설정된 클라우드 공급자로 전환하는 하이브리드 구조를 지향합니다.

Microsoft는 빠르고 구조화된 텍스트 답변을 위한 실험적 Decisions API도 함께 소개했습니다. Edge는 사이트나 기능이 처음 필요할 때만 Aion을 다운로드하고, 실행 가능한 기기에서만 모델을 사용하며, 사용자는 설정에서 온디바이스 AI를 끌 수 있습니다.

온디바이스 AI의 장점은 지연·비용·데이터 이동을 줄이는 것이지만, 모델이 작다고 해서 위험이 사라지는 것은 아닙니다. 웹사이트가 로컬 모델에 어떤 입력을 넘기는지, 클라우드로 전환되는 조건이 무엇인지, 모델 업데이트와 오픈 웨이트 파일의 무결성을 어떻게 확인하는지, 브라우저 권한과 모델 권한이 어떻게 분리되는지를 확인해야 합니다. 특히 로컬 추론과 클라우드 추론이 섞인 제품에서는 사용자에게 “어디에서 처리됐는가”를 설명할 수 있어야 개인정보·규제·디버깅 문제가 줄어듭니다.

### 6. Agentic Harness Engineering Beta: 벤치마크 패치보다 요구사항을 중심에 놓다

Jiahang Lin과 연구진의 Agentic Harness Engineering Beta는 에이전트 하네스를 벤치마크 점수만으로 진화시키는 방식의 한계를 지적합니다. 사용자 주도 평가에서 실제 요구사항을 이슈로 만들고, 팀 기반 수정으로 일반화 가능한 변경을 구현하며, 검증된 요구사항을 해결하고 리뷰를 통과한 변경만 병합하는 루프를 제안합니다. held-out 과제에서 pass@1을 21.9%에서 33.3%로 높이면서 토큰 사용량을 40.8% 줄였고, 사람의 블라인드 A/B 평가에서는 유효한 48쌍 중 31쌍에서 새 하네스가 선호됐다고 보고합니다.

## 결론

오늘의 제품 발표는 에이전트가 이제 대화 기능이 아니라 운영 시스템의 일부가 되었다는 사실을 보여 줍니다. Gemini는 운영체제와 앱의 화면을 다루고, AWS는 고객 업무를 Work plan과 Case로 바꾸며, OpenAI는 성능 회귀를 조사·수정·검증하는 루프를 자동화합니다. Genie 4와 Edge의 Aion은 에이전트가 활동할 가상·로컬 실행 공간을 넓힙니다. 캘리포니아의 정책 제안은 이런 행동을 독립적으로 검증하고 필요하면 중단할 수 있는 권한을 공공 감독의 문제로 끌어올립니다.

arXiv 연구는 그 운영 기준을 더 구체화합니다. 기억은 개발자와 공동 관리해야 하고, 사용자 시뮬레이터 자체도 실패를 감지하는지 시험해야 하며, AI 공급망의 조직 관계와 병목을 기록해야 합니다. 인간 검토자는 많이 클릭하는 사람이 아니라 실제 결과와 자신감이 잘 맞는 사람이어야 하고, 로봇 월드 모델은 예측을 개선하더라도 물리적 안전 제어를 대체할 수 없습니다.

**에이전트 시대의 최소 단위는 프롬프트가 아니라 사건입니다.** 사건에는 목표, 권한, 관찰한 근거, 계획, 승인, 실행, 결과, 검증, 되돌림 기록이 있어야 합니다. 이 연결고리를 만들 수 없는 자동화는 자율적일 수는 있어도 신뢰할 수는 없습니다.
